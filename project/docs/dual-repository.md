# 公开代码与私有资料一起使用

## 工作方式

公开仓库保存程序、提示词、版本化通用 Skill、人工测试和 CI。私有仓库保存原文、知识、审核及 Git 历史，并保留用于实际加工的工程副本。工程在公开 `dev` 开发，通过审查和准确提交的 CI 后，经 PR 交付 `master`。

公开 CI 只运行人工资料测试，不需要私库访问凭据。真实采集、加工、独立审核、发布和读取继续在获准的私有工作区执行。

## 分支配对

| 用途 | 工程仓库分支 | 私有知识仓库分支 | 对应 runtime 环境标识 |
| --- | --- | --- | --- |
| 开发与验证 | `dev` | `dev` | `dev` |
| 稳定／生产 | `master` | `master` | `prod` |

两边使用独立 checkout，并实际处于同名分支。`dev/master` 和 `master/dev` 都拒绝；初始化 `main`、其他功能分支和 detached HEAD 不参与运行配对。公开 CI 也必须来自这一共同分支，不能因同一个提交曾在另一分支通过就借用结果。

同名只确定对应关系，核心文件、版本、资料权限和生产发布条件仍须核对；版本未对齐时停止。核对不会切换分支、创建环境绑定、同步代码或把开发知识发布到生产。两库 Git 提交号与历史继续独立记录。

## 每次加工前核对一次

需要 Linux、Python 3.11 或 3.12、Git，以及能读取两个仓库和公开 Actions 结果的现有 `gh` 登录。核对脚本随完整 Git clone 提供；现有运行代码包不包含脚本和测试，不能替代这个工具所在的 checkout。不要把密码或令牌写入命令、Git 或测试资料。

```bash
python3.12 -B /path/to/code/project/scripts/check_dual_repo.py \
  --code-repo /path/to/code \
  --data-repo /path/to/private \
  --code-ref <公开代码的完整提交号> \
  --ci-run <该提交成功的Actions运行ID>
```

两边工作区先保持干净。公库 checkout 必须就是指定提交；两边按上表选择同名的 `dev` 或 `master`。入口实时核对：

- 公库可见性为公开，资料库为私有，两个仓库相互独立。
- 指定工程 CI 对应公库准确提交，且推送分支与两边的共同分支完全相同，六组测试和两组基础检查全部成功。
- 两边核心工程的完整路径集合、Git 模式和文件内容一致：`project/src/pdm/`、`project/prompts/`、`project/skills/`、`pyproject.toml`。

核对失败即停止本次操作，先处理明确的版本、工作区或权限差异。报告包含私库版本信息，只在私有位置保存；不要把报告附到公开仓库或公开 CI 日志。

## 使用私库现有命令

核对只证明报告时点的状态，之后修改工程需要重新核对。核对成功后，将模块加载位置和数据目录都指向私库。例如先检查运行条件：

```bash
cd /path/to/private
PYTHONPATH=/path/to/private/project/src python3.12 -B -m pdm doctor --repo /path/to/private
```

之后沿用私库获准的采集、加工和读取命令，仍须满足其资料授权、模型调用记录、审核、发布和环境绑定。报告放在仓库外，或明确提交到私库，再运行要求干净工作区的写入命令。

公库提交与私库程序提交分别记录。不要把公库提交号写成私库 `program_commit`，也不要用公库 CI 给私库不同提交补绿色状态；原生产交付门禁继续有效。

## 工程更新时

先在公开 `dev` 完成工程修改和 CI。按明确版本同步核心工程到私库 `dev`，仅提交实际工程变化，再运行 `dev/dev` 核对。稳定交付按已有审查与发布门禁处理，两边 `master` 再以对应的生产代码和 `master` CI 单独核对；不能把私库开发分支整库覆盖到生产来消除差异。私库资料、私人导航、CI、运行绑定及库外账本保留在原处，共用工程文档只在公库维护；历史 Skill 版本保持不可变，新增规则用新版本。

本入口不自动复制文件。当前两边工程一致即可直接核对使用；后续存在差异时，核对会拒绝继续，不能用“版本号一样”或只比较文件交集代替完整比对。不要 fetch、merge 或 mirror 私库历史到公库，也不要将私库 release 包直接当公开材料，因为其中可包含私人 README。

## 能证明什么

核对证明指定公开 CI 与私库当前工程副本的对应关系。人工测试、真实模型质量、真实资料加工及云端定时运行仍各自记录；一次核对成功不自动代替这些验收，也不启用新的模型或定时任务。
