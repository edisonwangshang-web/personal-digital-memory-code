| SQ09 独立审核有逐项结论 | 程序在调用前按固定规范及资料／候选范围生成必需 `check_id` 和作用范围；独立审核读取原文、画像、计算及候选，逐项返回检查证据和结果，程序拒绝缺项／重复／范围错配。检查准确性、遗漏、重复、分类、时间、限定及主题综合；对话／文章须回看原文，不只检查加工者列出的主张，也不宣称程序能证明语义无遗漏。总结论沿用 `passed`／`needs_revision`／`needs_confirmation`，可修复问题返工，原意确需用户决定才待确认，加载故障归执行失败 |
| SQ10 发布与分解审核 | 程序核引用、数值绑定、覆盖去向与 Skill 版本后才推进审核；发布消费全部必要检查和精确候选证明。object、coverage、global 分解单元各含实际所需规则和证据，汇合后覆盖全部义务；缺检查、把局部通过当整体通过或审核后改正文／Skill／计算依据均不得发布 |
| SQ11 兼容、返工与恢复 | 从固定提交／快照恢复 Skill、公共规范及必要依赖的实际内容并核摘要；只有 hash、内容缺失或尝试以最新版替换时阻塞。旧候选按原版本复验，不能回填 Skill 证明或改写历史结果；新版本需新候选绑定及独立审核。来源、规则及依赖改变后旧审核不放行新结果；未变有效阶段可核验复用，原 unknown、调用和有限重试身份保留，改 Skill／run／队列不清零或重发未知调用 |

上述门槛同时检查“内容有依据”和“本次应整理的内容有交代”。覆盖表各项都有状态，仅证明处置清单完整；审核仍须检查暂缓理由和最终概览是否有用，不能用全部填写 `deferred` 自动取得质量通过。

验收保留一组正确候选及有意加入的遗漏、错误数字、错误分类、过时状态和虚假引用反例；分别验证程序门槛与真实独立审核能阻止相应错误，并说明各自实际覆盖的检查。固定预期只供结果核对，不作为个人事实或答案提示交给模型。完成真实加工后检查主题页能回答“这段资料总体记录了什么、哪些指标缺失、能看出哪些可比变化、哪些暂不能判断”，同时复核相关领域目录、只读问答和引用；通过证据按真实调用记录，不以 Skill 文件存在、模拟输出或文档确认代替。

质量契约允许明确标识、可复算的派生统计，仍禁止擅自改写原列含义或补造未知单位。SQ01—SQ11的工程检查与真实模型结果分别判定，不能把隔离transport成功写成真实审核通过。普通返工／分解恢复纳入新质量验收；两个历史0.9 operator入口还没有新质量attestation，须验证其以`skill_quality_recovery_attestation_required`在调用前明确拒绝。其他M1真实增量、纠正、待确认、云端两轮触发与恢复门槛分别保留；可选跨模型读取不阻塞M1。

## 样本与验证记录

**真实样本：** 用户明确选定并提交的资料，保留原话、上下文、说话者和已知时间，按正常流程进入个人资料区。先用一段真实对话跑通，再增加同主题文章、跨平台对话、想法和后续补充。资料不存在就保留缺口，不虚构个人经历凑样本。

**隔离样例：** 下表中的假设文字、人工构造的冲突、故障与异常输入，仅用于解释需求或在隔离副本中演练，不能写入真实个人记忆。真实数据不足以触发某个异常分支时，可用隔离样例验证该分支；它不能替代真实资料的端到端演示。

每次验证记录至少写明：

- 验证的场景、真实样本或隔离样例，以及输入位置和版本。
- 执行前写好的问题、预期来源、预期状态与判断依据。
- 操作步骤、实际输出与来源链接；涉及发布时关联审核、对象版本和 Git 提交，涉及恢复时关联中断点和续跑结果。
- 通过或失败的具体原因、尚存缺口、修复项及复验结果。
- 实际入口或命令、最小配置名称，以及代码提交、依赖、模型、规则和样本版本；接手者按同一入口能够复跑。涉及凭证只记录配置名称，不保存密钥。

公开工程检查使用人工样例，可随工程保存可复现方法与不含个人内容的结果。真实输入、实际模型返回、审核／恢复及验收记录保存在私有工作区；公开文档仅描述证据是否具备及其限制，不链接私有材料。Roadmap 依据实际证据判断阶段，文档、候选或口头声明不算运行证据。

## S1—S8 基础场景

下列输入均是**明确虚构的人工示例**，只在临时仓库使用。真实业务验收须另选获准资料，不把这些示例变成个人事实。

| 场景 | 输入示例与操作步骤 | 预期结果与检查点 |
| --- | --- | --- |
| **S1 收藏文章、视频和附件** | 提交“收藏这篇学习方法文章和这份 PDF”及链接；检查保存回执；对可读内容执行加工、Review、发布，再问资料主要讲什么 | 能重新打开原链接和实际取得的内容；无法读取正文时明确未获取，不凭标题编造摘要，不把备注当原文，不宣称附件本体已备份 |
| **S2 沉淀跨平台对话** | 提交一段 Kimi 等平台的职业讨论；读回发言者与上下文；加工后问“我说了什么，模型建议了什么” | 每个结论定位到实际发言；区分用户自述与模型建议；只认已提交片段，不声称获得平台全部历史 |
| **S3 记录想法与明确决定** | 先提交“可以尝试每天读论文”，后提交“我决定每周读两篇，目前还没开始”；发布后问最后决定及执行情况 | 区分探索想法和明确决定；最终决定有原话依据；保留尚未开始，不把决定当成已执行，不补造决定的精确时间 |

| **S5 使用当天尚未加工的信息** | 上午提交“本月目标改成完成一门课程”，每日任务前询问当前目标；比对回答前后的正式文件 | 能用当天原文并标明未加工或未审核，解释与旧目标的差异；回答不绕过 Review 修改正式知识，也不自动成为新证据 |
| **S6 自动三领域与跨类共享** | 分别提交获准的健康&运动、工作事业、学习&能力提升新输入，再提交“调整加班安排，留出运动和英语练习时间”的跨类表达及无关／未定输入；process提取＋独立Review后，以限定knowledge目录查看 | 自动输出不重复health／career／learning，可跨类或[]，必要原意待确认；同一事实只存一份、目录共享同一版本，不把设想当执行。旧精确reuse保留旧标签；目录尊重控制／缺口，不推断全库最新 |
| **S7 集中处理需要确认的内容** | 提交“计划下个月开始，具体哪一天还没决定”；同时提交一条无关的明确信息；重跑，再给原事项补充回复 | 未知日期不猜测；只有影响理解或加工的问题入清单；同一问题不重复生成，无关通过项正常发布；回复作为新证据关联原事项，处理后更新事项 |
| **S8 每日加工与失败重跑** | 在隔离副本模拟 Git 已提交而发布回执中断；恢复同批次，再检查未完成输入 | 先核对远程已有提交，补回执并只续跑剩余部分；不重复入库或重复确认项；结果准确说明成功、待确认、失败范围 |

### 从一次对话到知识文件

以 S3 的假设对话检查整条路径：

1. 原始区保留两次发言、说话者和先后顺序，不能只留下最后一句摘要。
2. 候选区区分探索想法与明确决定，按数据规范形成独立记录；决定时间未知就保持未知。
3. 独立 Review 对照原文、候选和相关旧记录；审核记录能定位它审过的具体版本。
4. 通过后发布决定记录及相关学习主题页，运行回执能找到实际提交；主题页与记录分别保留依据。
5. 询问“我最后决定如何读论文，开始执行了吗？”答案引用最后决定的原话，并说明尚未开始。
6. 从远程重新读取原文、记录和主题页，核对文件、链接和审核版本，证明不依赖本次临时目录。

原始区、候选区、正式记录和主题页是逻辑角色；实际目录以数据规范为准，不能为了演示同时维护两份独立事实。执行这段假设流程本身不表示已经采集真实资料或创建每日任务。

| 累计启动数与当前失败分开 | 提取已启动后，在Review启动前令预算账本失败；本次错误attempted_calls保持0，operation_started_calls仍保留此前实际启动的1；不回退为0，不退款、不重放。启动前失败不能虚增started |
| 兼容与交付范围 | 既有Review／发布、pending、预算与异常清理回归保持；schema及真实memory不变，真实账本不重建，不把本批隔离通过记为runner／纠正或可选跨模型读取的实际通过 |

来源分组与多Wiki按现行batch／group契约检查，QA结果持久化按实际任务需要补齐；普通删除、并发和中断恢复可按原方案隔离验收，不新增真实个人删除要求。M1整体仍须原执行方案的多来源增量、真实纠正／待确认、两轮目标runner触发及恢复证据。

### 回答引用的通用语义核对（answer v8）

以下均为临时人工来源和人工预期，用于定义检查方法，不表示真实模型已经通过。三个领域共用同一回答规则和输出结构，不增加一个模型审核阶段。

| 人工来源 | 合理陈述与引用 | 应退回的陈述或引用 |
| --- | --- | --- |
| 健康：L1「运动报告」；L2「覆盖某月」；L3「只有部分日期佩戴」 | 「覆盖该月，佩戴并不完整」，引用 L2-L3 | 仅引 L1-L2 证明「完整佩戴」或「只有部分日期佩戴」；标题和日期范围不支持佩戴情况 |
| 学习：L1「课程A」；L2「计划学习」；L3「尚未完成」 | 分别引用 L2 的计划与 L3 的未完成状态 | 引标题或计划证明「已经完成课程」；不能把计划当执行结果 |
| 工作：L1「项目A」；L2「提出方案建议」；L3「用户尚未采纳」 | 「这是建议，尚未采纳」，引用 L2-L3 | 引项目名或方案建议证明「用户已经决定采用」；不能把建议当用户决定 |

检查最终 JSON 中的每个实质陈述、正文编号、`citations` 条目及实际原文行是否一一对应。依据来自不同位置时拆句或分别引用；同时依赖多来源的结论应带齐各项依据。不能用很宽的行号或包头引用掩盖依据缺失。缺少支持时缩小陈述并说明限制，不补造事实。

实际 QA 输入只含规则、获准资料和预先固定的问题，不含本表的标准答案、预期编号或验收结论。保留首次失败及明确反馈后的实际结果；合法编号和存在的行范围只证明结构，不能代替语义核对。规则升级不重写旧答案，也不要求重跑已完成知识提取。

### M0 独立会话验证

公开验收方法检查来源追溯、缺口表达、状态与时间区分；真实 M0 样本和实际结果仅存私有证据。以下演示材料是重新构造的虚构样例，不复制历史真实请求，不表示用户曾提出该内容：

```text
L1 示例名称：虚构实验项目
L2 发言者：人工测试用户
L3 原始消息时间：未知
L4 内容：请帮助我整理这个合成实验项目。
```

| 编号 | 独立调用中只提供的问题 | 验收者预先固定的内容与证据 |
| --- | --- | --- |
| M0-Q1 | 这条资料提出了什么请求？ | 忠实表达L4的整理请求，不补造具体功能、计划或期限 |
| M0-Q2 | 只依据这条资料，能否确定开发范围、验收标准和完成期限？ | 明确材料不足以确定；不能用当前工程文档或模型建议补成样例中的决定 |
| M0-Q3 | 这条资料能证明项目已经完成吗？原始消息时间是否已知？ | 请求不证明完成；L3标明未知，不能用采集、发布或Git时间替代 |

上表预期和预选引用只供验收者核对，不进入模型问题、提示词或证据包。模型只取得固定版本的限定持久文件、必要回答规则及问题，保留原文自身行号，自行选择引用；不能读取本验收文档、当前聊天、前题答案或验收者结论。真实验收在执行前按获准原文固定问题及预期，不沿用虚构事实。

1. 调用前固定程序提交、回答规则、数据HEAD、来源ID／版本、正式记录／主题版本及字节摘要，以及对应发布与审核依据。证据须实际包含原文、正式记录与主题正文，不能只有状态或路径。
2. 三个问题各用新的独立模型调用，不继承原聊天、前题回答或加工／审核上下文。模型标识未知时保留unknown，实际调用身份与证据留私有工作区。
3. 核对实际答案、来源ID／版本／行号、原文字节和主要结论。正式记录和主题是受审派生内容，不能增加独立证据；模型自评不代替核对。
4. 固定实际输入范围和证据摘要，证明标准答案未入输入。问答前后HEAD、工作区和受管文件字节不变，不写来源、候选、审核或正式知识。
5. 从相应远程重新取得干净副本，按固定版本核对来源、正式对象、主题和引用；依赖原临时目录才能读到的内容不算恢复成功。人工工程演练使用临时远程，真实资料恢复始终私有。

本节固定方法，不预填通过。M0通过不能替代每日任务或其他M1门槛，也不证明可选跨模型读取已经完成。

### 可选跨模型读取验证（非 M1 门槛）

如后续选择做跨模型验证，在获准使用的另一模型中，读取与第一模型相同的**限定资料包及版本**，回答同一组事实与来源问题。记录读取范围、模型、输入版本、答案和引用，比较事实、当前/历史状态与证据定位是否一致；不要求措辞相同。

不能只把第一模型生成的答案交给第二模型复述，也不能假定任意模型都获得全库权限。另一模型无法访问资料时，先记录接入失败；不能把“格式理论上通用”记为已迁移成功。未验证时如实记录未进行，不阻塞M1。当前Agent通过目录和文本查找定位知识，再按明确范围使用现有CLI读取；不因保留本节就自动启用任何模型或取得全库外发权限。

## 每日运行与恢复验证

以下是 M1 的建议检查口径，执行时间和结果需按实际发生记录。

| 检查 | 执行方式 | 通过证据 |
| --- | --- | --- |
| **真实每日增量** | 在实际定时环境完成两次触发；两次之间提交新增资料，再补录一条较早发生的资料，保留部分未完成输入 | 后一轮处理新增、变更、补录和允许续跑项；未变且已完成的内容不重复发布；两次均有实际触发和运行记录 |
| **未触发、未完成与空批** | 在隔离环境分别模拟预期时刻未触发、已触发但无结束回执、正常运行但无新输入，再执行状态查询；另检查平台触发记录不可读的情况 | 分别说明未触发、未完成／待核对、正常空批或无法确认；不把无回执当作成功；能列出未处理范围。真实每日运行仍单独验收 |
| **暂停与重新启用** | 在隔离环境准备待发布批次后暂停，另模拟已提交但回执未到；保留新增原文，修复或恢复兼容程序版本后复验并启用 | 暂停后不接受新的正式发布；在途结果先查远程；重启无重复写入；新增原文与删除控制保留，已发布错误走纠正流程，受影响答案标明待核对 |
| **发布门禁** | 在隔离副本直接向发布适配器提交缺少 Review、Review 指向其他对象的变更包；复用下列版本变化用例检查版本绑定 | 适配器实际拒绝写入，远程正式文件未变，返回可定位的拒绝原因；仅由模型回答“不能发布”不算通过 |
| **无索引读取与缺口** | 复用 S4、S5：保存纠正但不加工，通过文件读取和文本查找回答当前状态；再限制读取预算，使相关材料无法全部检查 | 能发现未加工纠正并说明状态；预算不足时记录已读和未读范围，回答说明缺口，不宣称已检查全部资料或确认最新状态 |
| **候选版本变化** | 在隔离副本先审核候选 A，再实质修改为 B，尝试沿用 A 的审核结果 | 发布被阻止；B 重新校验及 Review 后才能发布；审核能区分版本 |
| **相关依据变化** | 审核后修改本次依赖的来源或旧记录，再尝试发布 | 检出变化并重新合并和审核，不以旧 Review 掩盖新依据 |
| **提交后中断** | 在隔离副本于 Git 提交成功、回执未保存时中断，再从持久状态恢复 | 找到已有提交并补齐回执，正式对象、Wiki 和待确认事项没有重复 |
| **并发更新** | 在准备发布后通过另一操作更新目标仓库，检查相同对象及无关文件两种情况 | 不覆盖其他更新；相关记录变化触发重算与重审，无关变化得到保留 |
| **普通删除** | 在隔离副本删除一项正式内容及相关展示，留下禁止自动重建控制；重跑原来源并进行即时问答 | 当前知识与问答不再无意恢复删除内容；Wiki 和引用得到处理，Git 历史仍可回溯；不宣称历史已清除 |
| **有限重试与临时目录丢失** | 让调用达到预算或重试上限；清理本次临时工作区后从持久文件续跑 | 保留已完成与剩余范围，任务能够结束；后续从实际存储恢复，无无限循环或重复发布 |
| **本地副本恢复** | 从私有远程重新取得获准文件，核对原文、记录、主题页与引用 | 内容和版本与远程一致；附件只验证链接，不能把它记为附件本体恢复 |

定时环境必须实际完成“读资料 → 加工 → 程序校验 → 独立 Review → 发布控制 → Git 写回 → 读取结果”的整条路径。配置界面存在任务或某个模型生成了结果，都不替代这一验证；失败时定位具体受限环节。

两轮每日验收开始前记录程序、规则与配置版本。若中途修复改变定时链路，在修复版本重新取得两次真实触发证据，保留前次失败原因；不能把不同实现下互不兼容的两次结果拼成一次通过。状态查询和停启规则见[实现明细](implementation-details.md#51-状态查询暂停与重新启用)。

首次接入先在实际定时执行环境用隔离样例探测上述能力，记录可用工具、执行权限与阻塞点。交互会话能写 Git，不代表定时任务具备同样权限；任一必要能力缺失时，保留手动试跑结果，不标记每日链路通过。探测结果关联当次环境与权限配置，配置变化后重验受影响能力；日志只留必要标识与失败原因，不复制完整个人资料。探测成功后，仍须完成上表的真实每日触发和增量验证。

## 首批问题与预期证据

建议逐步积累 **5–10 个中文问题**，运行前标出预期来源，先用同一组资料回归，再扩展范围。下列问题按现有真实资料选择，不为凑数量而制造个人经历。

| 检查重点 | 可使用的问题 | 执行前标出的预期证据 |
| --- | --- | --- |
| 原文追溯 | “这条结论是我说的，还是模型建议的？” | 对应发言者、来源版本和原文位置 |
| 一段原文多个对象 | “这段讨论里，我想达成什么、决定了什么、实际做了什么？” | 目标、决定和已发生事件各自的证据；没有实际行动就标未知或未发生 |
| 当前与历史 | “现在是什么情况，和上次相比变了什么？” | 适用时间、明确更新或纠正关系，不能仅靠写入时间 |
| 用户采纳 | “这项建议我已经决定采用了吗？” | 用户采纳原话；没有就保留建议状态 |
| 当天新信息 | “今天补充以后，现在应该怎样回答？” | 未加工原文和旧记录，说明差异与审核状态 |
| 资料缺口 | “现有资料足够解释这个结论吗？” | 已取得内容与缺失证据，不凭标题或空白补造 |
| 分歧与待确认 | “有哪些地方还需要我确认？” | 对应清单事项、双方依据及影响范围 |
| 删除与历史 | “删除后还能在当前知识里看到这条内容吗？” | 当前文件与禁止重建控制；历史回溯单独解释 |

独立会话的三个来源问题可计入这组问题。对于重复提交、审核变化和中断恢复，除问答外还应直接检查文件、版本和实际提交，不能只根据模型解释判断通过。

## 质量门槛

以下为首批建议验收要求，应在真实试跑前固定到验证记录中。门槛有调整时说明原因，并复验受影响样本，不用降低要求掩盖已发现的关键错误。

| 检查范围 | 必须能证明什么 |
| --- | --- |
| 原文与独立记录 | 原文、独立知识记录和 Wiki 关系清楚；不能只留一页摘要作为唯一记忆；一个来源多个对象时保留关联和上下文 |
| 来源与语义 | 每个主要结论能追到准确来源版本和位置；说话者、限定条件、适用范围没有遗漏或扩大；不同人物、时期或对象不能误合并 |
| Review 与发布 | 结构检查和独立模型 Review 均有效；正式内容与审核版本一致；远程提交和读回可验证 |
| 状态与时间 | 来源、核验、审核、用户采纳和执行情况按数据规范分别表达；不把建议当决定、计划当完成、待审当正式；未知时间不补造；已提交的执行反馈保留对应的当时计划版本 |
| 当前与派生维护 | 新依据能影响回答及直接依赖的知识；历史变化与错误纠正分开，受影响 Wiki 重新检查；不得从原文路径绕回旧错误 |
| 回答与缺口 | 关键证据找得到，相关未处理增量会检查；能解释分歧与缺失资料；生成回答不自动成为独立证据 |
| 恢复与一致性 | 同一输入不重复建对象，已发布内容不重复提交，互相依赖变更一致发布；失败范围可续接、待确认不阻塞无关项 |

首批样本应全部满足来源可追溯和 Review 门槛，且没有表中状态混淆等关键错误。其他质量问题也需明确影响范围、修复工作和是否影响场景使用；未解决的关键失败不能标为通过。

第一版保证已经提交的目标、决定和实际经历被正确记录与区分。个人分析、计划和复盘的专项验收随 Roadmap 对应阶段补充，必须使用相应真实问题或实际执行反馈，不能用模拟行动记录替代真实完成。

## Foundation dev2 隔离回归

本批自动回归覆盖来源0.1不变与0.2元数据共存、限定来源／回执、两次不同调用、缺失／未通过／变化后的审核拒绝、路径与引用越界、CRLF原样引文、程序／规则／HEAD变化、正式字节篡改、原子提交、回执补齐与受限事务恢复。测试仅使用临时人工资料，不调用真实模型。

## 普通auto恢复与账本归属

人工隔离反例：候选无revision字段、无execution_context，原账本A的extract completed而根Review unknown；公共resume换空账本B或A中新operation，必须零模型／零Git写并拒绝。completed extract的invocation或payload SHA不符同样拒绝。同原A原operation且Review安全预启动失败时，允许对同一固定候选完成分解审核，再核发布及current／historical。后继门禁只读兼容核验不能重标实际提取版本；真实结果与原始调用版本分别留在私有证据中。
