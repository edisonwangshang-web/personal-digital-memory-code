# Roadmap：知识、分析、计划与复盘

项目目标是将主动提交的资料保存为可迁移、可追溯的知识，再逐步支持有依据的分析、用户确认的计划和实际反馈复盘。架构沿用人机交互、个人知识与决策、公共工程能力、数据与存储四层，阶段定义以本页为准。

产品方案、技术设计、实现规则、工程使用说明和项目进度统一在公开工程仓库维护。个人来源、知识、真实审核、业务验收和私人接续材料保留在私库，公开进度不附这些原始证据。文档分层入口见[总体方案](overall-plan.md)、[技术方案](technical-plan.md)、[实现明细](implementation-details.md)、[数据规范](data-conventions.md)与[场景验收](scenarios-and-acceptance.md)。

## 当前阶段

当前程序为 `0.2.0.dev19`，新任务默认 `knowledge-extract@8`／`knowledge-review@6`，基础规则为 extract v14／review v10／answer v7。M0 手动基础闭环已有历史验收；M1 已实现主要工程能力，**整体仍未验收**。M2—M4 尚未作为完整产品阶段交付。

公开工程已核对的快照为 [`8e461422712252ccffefe664466c1ba254fc97cf`](https://github.com/edisonwangshang-web/personal-digital-memory-code/commit/8e461422712252ccffefe664466c1ba254fc97cf)，其 [CI 40163471251](https://github.com/edisonwangshang-web/personal-digital-memory-code/actions/runs/40163471251) 八任务成功，Python 3.11／3.12 各 1004 项及基础检查通过。该结果只属于这个提交，不能视为本页后续文档 HEAD 已通过。

公库 `dev` 开发、`master` 稳定交付；真实加工继续从私库工程副本加载。只读入口核对准确公开 CI 和两边完整核心工程，当前快照为 71 文件；不自动复制或同步，不替代私库不同 SHA 的生产门禁。操作见[双仓库实际使用](dual-repository-operation.md)，CI 路线见[公开工程 CI](public-code-ci.md)。

## 项目级里程碑

| 阶段 | 用户可演示的成果 | 状态与依赖 |
| --- | --- | --- |
| M0 记得住、找得回 | 离开原会话后仍能找到已选原文及经过审核的知识，分清请求与完成事实 | 基础手动闭环已完成；实际验收依据留私库 |
| M1 知识库持续积累 | 新资料有覆盖依据和时间边界，补充或纠正能更新知识和答案，持续运行可恢复 | 工程持续完善，整体待验收；依赖下述四组出口 |
| M2 结合已有记录分析 | 分析能说明事实、约束、可能解释、选择与缺口 | 待建设，依赖 M1 当前知识及具体问题所需资料 |
| M3 将选定目标变为计划 | 用户知道下一步、投入、依赖与完成标准 | 待建设，依赖用户明确选择的目标与现实约束 |
| M4 根据实际结果复盘 | 对照原计划与反馈，决定继续、调整或停止 | 待建设，依赖计划版本与真实执行反馈 |

每阶段都贯通输入、加工、保存与使用。先在明确的小范围跑通，再扩大规模；资料不足时保留缺口，不用测试样例填充个人事实。

## M0：记得住、找得回

基础能力包括保留原文与未知时间、幂等采集、独立提取和 Review、原子发布、限定范围问答、引用核对及完整 Git 恢复。验收须能区分原始表达、已审核整理和当前完成状态，不能用工程文档补造用户原话。

M0 的历史完成不等于整个项目已完成、已部署服务或 M1 通过。公开代码保留通用能力与兼容规则；实际问答、资料版本和私有恢复依据在原私库独立管理。

## M1：知识库持续积累

M1 聚焦可日常维护的知识库。用户明确提交文章、对话、个人想法及后续补充，系统保存原文、自动分类、提取整理、独立审核并发布；提问时说明选定范围、来源、时间与待确认事项。

| 验收组 | 已有工程能力 | 尚需完成的退出检查 |
| --- | --- | --- |
| M1-01 多来源、领域与增量 | 显式多来源加工，条件更新／复用，三领域目录，Skill 绑定，覆盖清单、描述统计与时间限定 | 按获准业务范围确认代表性真实资料、增量持续维护、跨类／未分类及质量出口；各资料链分别验收 |
| M1-02 补充、纠正与待确认 | current evidence、对象级控制、统一 pending、答复关联与发布后解决核验 | 真实补充／纠正的加工前后对照，以及答复→审核→发布→解决闭环 |
| M1-03 每日运行 | 持久计划、分批、有限重试、发现／drain、停启与实际远程确认接口 | 目标 runner 能力、持久 checkout／状态／权限，22:00 两轮真实触发及期间新增／变更／补录／续跑 |
| M1-04 恢复与第二模型 | 事务恢复、删除防重建、历史核验、限定读取包及工程隔离回归 | 目标环境状态恢复，获准另一模型实际读取同包同版本、独立回答并核对来源 |

过关演示应能回答：选定范围的资料是否整理、现在有哪些受支持的结论、依据在哪里、哪些问题需要确认。表格资料还要交代期间、缺失、有效样本和可复算变化；提交真实补充或纠正后，知识与答案应出现对应变化。

只有四组出口和下面的质量检查全部取得证据，才宣布 M1 完成。单条加工链通过、正式对象数量增加、工程测试成功或一次远程恢复都不能代替整体验收。

## M1 知识质量与 Skill 引用工作包

模型负责组织内容和独立语义审核，程序提供可复算材料、精确版本与条件发布检查。知识应说明自身来源、时间和范围；描述统计不直接变成原因分析或行动建议，后者属于 M2。

| 工作包 | 工程能力与质量出口 | 当前边界 |
| --- | --- | --- |
| M1-Q01 显式 Skill 引用 | 分别装载提取／审核角色，展开必要依赖、固定规则快照并绑定实际请求；缺失或版本不符时停止 | 已实现；旧任务恢复使用原 bundle，历史 Skill 保持不可变 |
| M1-Q02 清单与描述统计 | 核对日期、指标、结构列、缺失／零／异常、有效样本和计算口径，固定原文可复算 | 已实现；同源重复不充当独立证据，不猜单位或补值 |
| M1-Q03 知识组织与时间 | 正文交代各目标去向、适用的期间水平与可比分段；记录与主题自身说明范围和限制 | 已实现；结构齐全仍须实际内容与语义检查 |
| M1-Q04 独立质量审核 | 对照原文、清单、统计、时间和候选逐项审核，完整证明绑定精确版本后由发布者消费 | 已实现；修订后重新审核，旧证明不放行新内容 |
| M1-Q05 回归与业务验证 | 用人工反例检查加载、版本、分批、恢复、误算、漏项、误类和时态，再做限定真实业务验证 | 工程回归与真实业务证据分开；具体实跑记录保留私库 |

当前默认 `knowledge-extract@8`／`knowledge-review@6` 与共享 `knowledge-quality-v1`、`knowledge-context-v1` 协作。质量链、queue／attempt、日程事件与分解 proof 为 schema `0.10`；来源 `0.1`、正式对象 `0.2`、group wrapper `0.6` 保持兼容，不自动迁移旧资料。

普通质量返工和分解恢复沿原规则继续；两个历史 `0.9` 人工 operator 入口不接收新质量链，缺少适用证明时停止。完整技术职责、字段与用例分别见[技术方案](technical-plan.md)、[数据规范](data-conventions.md)与[场景验收](scenarios-and-acceptance.md)。

## M2：结合记录分析问题

在 M1 的受审知识上，分析事实、约束、选择与不确定性。三个领域使用通用原则，但应分别有适用的真实问题和事实核对，不能把一般建议当作已经结合个人情况。

| 建设顺序 | 成果与检查 |
| --- | --- |
| 形成问题上下文 | 读取相关当前知识、历史变化、目标和约束；过期情况不无条件沿用 |
| 领域分析 | 区分原始记录、外部方法与模型推断，每项判断说明依据和未知条件 |
| 比较选择 | 指出时间、资源或目标冲突，给出可比较方案与取舍 |
| 验证实际问题 | 健康、事业、学习各核对代表性问题，追问哪些证据支持判断、什么缺项会改变结论 |

长期保存的分析沿用审核发布流程；用户未选择的建议不自动成为目标。是否拆分独立 Agent 由实际维护需求决定。一个方向跑通后可试跑对应的 M3／M4，但 M2 整体仍需三个方向分别有证据。

## M3：将选定目标变为计划

先保存用户选定的目标、成果、可用时间与期限，分清建议和决定；再比较少量路径，列出步骤、投入、依赖及取舍。用户选定路径后，拆出近期行动、顺序、检查点和完成标准，并保存确认版本。

验收应能回答“下一步做什么、为什么先做、做到什么算完成”，且安排符合实际约束。未确认部分保持候选，修改保留原因和旧版本。生成计划不代表用户已执行，外部日历或任务工具写入按实际需要另接。

## M4：根据执行结果复盘

保存实际完成、未完成、投入、结果与阻碍，关联原计划版本；没有反馈的行动保持未知。对照检查点区分执行偏差、目标变化和资料不足，再给出继续、调整或停止的选项。原因不清时明确缺什么，不把猜测写成事实。

用户确认后更新计划版本，保留上一轮计划与结果。退出要求至少一个真实的分析→选目标→计划→反馈→复盘→确认调整周期，不能用模拟完成记录替代实际反馈。
