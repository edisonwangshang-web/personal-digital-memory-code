# M1 工程交付与业务验收

本页把工程修复的交付条件与完整 M1 的业务出口分开核对。当前先人工触发，完整阶段状态以 [Roadmap](roadmap.md) 为准；代码进入 `master` 不表示定时服务已部署，也不表示可以发布 M1 完成版本 `0.2.0`。

本批dev29仅在dev开发验证，不合入或推送master。补符合有限合同的提取timeout自动最多3次重试，原unknown与次数保留，不适用的未知调用仍停止；本批针对性人工回归已检查，准确dev CI待核，真实全链另行验收；下文稳定分支流程保留作历史与后续操作规范，本批不执行。

## 本批工程检查

以下检查使用临时 Git 仓库、人工资料和模拟模型，真实输入、输出及私有证明不进入公开 CI。每项以实际测试结果为准，不预填通过。

| 范围 | 必须观察到的结果 |
| --- | --- |
| 多批容量与依赖 | 资料拆批后，在完整语义和必要依赖可承载时推进真正最终候选、独立审核与发布；无法安全组合则保留具体阻塞范围，不截断必要原文，不把草稿标为正式结果 |
| 审核反馈续接 | 草稿和答复续接收到 `needs_revision` 后带实际意见返工；新候选重新审核，原失败、未知结果及持久次数保持，换队列或计划不能刷新次数 |
| 阶段材料 | 新普通Review按`current-draft-v1`取当前稿、质量检查及对应证据，不重复发送返工／恢复链；被退回稿带marker时，返工extract取最新稿、未解决意见和必要证据，完整真实反馈仍持久核验，旧无marker投影／请求字节保持，不增加合同或模型阶段 |
| 纯绑定返工 | 新11/9、普通quality0.15，仅真实纯缺失时在原revision extract补statistic_bindings；正文／关系／原有quality条目固定、value和根引用可复算，完整新Review及原次数保持；混合内容仍走原全稿 |
| 调用等待与有限timeout重试 | 新普通CLI默认900、允许1—1800秒并传到实际调用；专用旧恢复默认120兼容，冻结日程不迁移。仅默认冻结策略且窄范围适用的root提取自动最多补3次，总4次；原unknown和次数保留，不适用调用仍停止 |
| 选择性读取 | 单次证据构建内减少重复的固定 SHA Git 读取，保留完整证明核验；来源、候选、审核、控制或工作区发生变化仍拒绝，不用缓存掩盖变更 |
| 调度结果 | `run` 与 `drain` 对需对账或人工处理返回失败退出码；合法等待和可继续的部分进度不误报成功完成，也不被当作永久失败 |
| 控制容量 | 新控制超容量时在提交前拒绝，HEAD 和资料字节不变；已有相同控制在容量边界仍可幂等读取，不发生部分删除 |
| 回答引用 | 通用规则要求逐句核对陈述与引用行；编号、坐标和版本检查继续生效，语义支持仍由实际答案核对，不能仅凭程序检查宣称可靠 |

先运行受影响检查，集成后在准确提交上完成公开工作流规定的双 Python 全部测试分片、doctor、源码归档边界和代码包核验。检查范围与命令见 [本地检查](local-checks.md) 和 [公开 CI](public-code-ci.md)。本地报告不能代替 GitHub 的实际状态。

## 工程进入稳定分支

1. 在公开 `dev` 完成修改、审查和准确提交的实际 CI，PR 说明最终行为、验证及剩余边界。
2. 用同仓库 `dev` 向 `master` 提交 PR，核对 PR 的实际合并树和全部检查。使用保留祖先及父边的 merge commit，不 squash 或 rebase。
3. 合入后再核对实际 `master` 提交及其 CI；不同 SHA 的旧结果不能代替。本批工程版本、规则和支持格式分别固定，不建立 M1 已完成的标签。
4. 生产使用前，另核公库 `master` 与私库 `master` 的同名配对、准确 CI、工程来源、资料边界、兼容性及 `prod` 环境绑定。私库生产资料、控制和历史保持，不将 `dev` 个人资料整分支合入。

私库稳定分支若仍有活动工程副本，应在私库以保留历史的独立资料边界修改处理；不能把公库代码复制回去，或将私库历史导入公库。操作规则见 [双仓库实际使用](dual-repository-operation.md) 及 [发布与回滚](release-and-rollback.md)。

## 完整 M1 尚需的实际证据

| 出口 | 工程测试之外的通过依据 |
| --- | --- |
| M1-01 多来源与增量 | 获准代表性资料的新增、变更、补录、关联更新，以及三领域、跨类和未分类的实际质量；单一领域样本不证明其他场景已通过 |
| M1-02 纠正与待确认 | 一次真实补充或纠正的加工前后对照；具体问题、真实答复、重新审核发布及事项解决的完整关系 |
| M1-03 每日运行 | 目标 runner 的真实入口、限定权限、持久状态及读写能力，两个北京时间 22:00 实际触发及期间增量、停启和续跑记录 |
| M1-04 恢复与第二模型 | 目标环境的状态恢复，以及获准另一模型读取同一限定资料包和版本后独立回答、核对来源 |

没有真实纠正事实时不编造个人错误；没有可执行定时入口时不拿本机手动命令或 CI 代替；读取包核验成功也不等于另一模型已经读取。既有成功资料链继续保留，不因工程升级重新全量提取，不重置原有限次数或重发未知调用。以上出口全部取得证据前，M1 保持未验收。
