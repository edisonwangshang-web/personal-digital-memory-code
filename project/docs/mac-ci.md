# Mac 上的 Linux 容器 CI：可选方案

公开工程当前使用 [GitHub 标准托管 Linux CI](public-code-ci.md)，不要求 Mac 常开。本页保存曾评估的 Mac 容器路线，供有明确自托管需求时参考；本公库未提供专用 Mac 启动工具，Mac 主机、真实注册和完整 Actions 链路均未在本路线验收。

## 运行位置与前提

可选结构为 Mac → Docker Desktop → Linux 容器 → GitHub 自托管执行器。真正执行任务的是容器，注册时的系统和架构应与容器一致。自托管通用接入与验收要求见[自托管 CI](local-ci.md)。

先安装并启动 [Docker Desktop for Mac](https://docs.docker.com/desktop/setup/install/mac-install/)，在 Mac 终端检查：

```bash
uname -m
docker --version
docker info
```

`x86_64` 通常对应 Intel，`arm64` 通常对应 Apple 芯片。若选择 Linux/amd64 容器，Apple 芯片需要受支持的 amd64 仿真，其速度与兼容性须实测；不能只改执行器标签掩盖架构差异。Docker 的许可与使用条件按当时官方说明核对。

## 工具开发与隔离要求

采用前需要另行提供并审查镜像、离线检查、注册、状态、停止与卸载工具，不能从本文推断这些工具已经随公库交付。镜像检查应覆盖实际架构、非 root 运行、Git／Python／runner、必要系统接口和防覆盖原子文件操作。

镜像构建上下文只包含必要工具；原文、知识与完整私有历史不得进入构建层。建议使用专用容器状态卷，避免挂载宿主目录、`docker.sock` 或使用 `--privileged`，不把宿主模型／GitHub访问环境直接传入容器。卷内可能保留机器认证和工作目录，应按私有状态管理；停止容器不等于删除这些内容。

运行时需保持 Docker 和执行器在线；Mac 睡眠、合盖、关机或容器停止都可能造成任务排队。是否使用防闲置睡眠工具应由操作者在本机决定，不能承诺跨关机持续运行。

## 分层验收

| 检查 | 能证明什么 | 后续仍需什么 |
| --- | --- | --- |
| 镜像离线检查 | 固定镜像具备必要工具与系统接口 | 在实际 Mac 上运行并核对架构与卷行为 |
| 容器运行与状态检查 | 本机容器进程存在 | GitHub 注册成功、Online 与标签匹配 |
| GitHub Online | 机器已连接 | 对准确提交实际执行全部 CI |
| 完整 Actions 成功 | 指定提交完成所需工程检查 | PR 合并上下文、发布与业务验收各自核对 |

一套可用方案还需验证卷归属、停止再启、清理、升级及资源不足时的失败行为。不要用另一宿主的镜像检查、一次 Online 或旧本地报告代替这些结果。未完成接入时，继续使用公开托管 CI；离线开发可在 Linux／WSL2 运行[本地检查](local-checks.md)。
