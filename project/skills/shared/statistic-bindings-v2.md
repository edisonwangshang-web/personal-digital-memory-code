# 统计关联共同口径 v2

本规则由提取13／审核11共同加载，健康、工作、学习及未分类资料使用相同口径。只约束当前实际提供的正文、目标、程序统计与来源；不扩大资料权限，不迁移旧声明或旧审核结论。

- 每项正文实际表达的程序统计都要有准确的stat_id、record_id和对应正文摘录。统计身份由所属目标、根来源及版本、计算种类、单位、期间与样本／扫描范围共同确定；数值相同或来自同一表不能证明是同一关联。
- 正文用“各项”“逐项”“全部上述指标”等集体表述明确将同一个扫描分母或其他统计适用于多个指标时，对每个实际被该表述覆盖、且程序确实提供相应统计定义的目标，逐项声明准确关联。可使用同一段完整正文摘录，不必在正文反复写同一数字，也不需要复制全张表。
- 正文只陈述某一个字段的统计时，只要求该实际字段的关联；不向没有被表述的其他指标强加关联，不要求把整个statistics目录搬进正文。适用对象、分母、单位或期间有歧义时，应先澄清正文或按真实证据缺口处理，不以数值相同自动推断。
- 提取和审核使用以上同一口径。旧声明是否曾获passed既不替代本轮核对，也不授权模型临时增加别的关联标准。审核应指出具体正文及缺失的目标／统计身份，不能只写“关系不全”。
- 审核确认仅缺统计关联时，repair_scope.kind为statistic_bindings，missing_bindings每项严格提供stat_id、record_id、body_evidence；body_evidence须为该指定记录正文中的准确非空摘录，保留理解适用指标、期间、单位和分母所需的限定。不能只在reasons里写摘录，不能用Wiki代替记录正文。
- 对具有真实审核绑定的statistic-bindings-repair-v2请求，missing_bindings已固定上述三项；补丁仍按现有提取调用返回相同三项。程序机械展开value、根来源、locator与quote并验证，正文和既有声明冻结。审查过的摘录不是新的原文事实，机械展开不等于语义正确；物化后仍完整独立审核。
- 来源、正文、已有数值或关系需要改变，或完整最终候选仍有已知内容缺项时，不得把整份候选当作仅缺统计关联。真实缺料仍走现有待确认，内容问题仍走完整内容返工；不增加阶段、调用权限、发布豁免或重试次数。
